# CANVAS-BASED DASHBOARD REFACTOR PROMPT

You are a Principal Product Designer, Creative Director, and Senior Frontend Engineer.

Refactor the entire E-Learning dashboard from a traditional card-based layout into a modern canvas-based experience.

IMPORTANT:

Do NOT redesign the brand.
Do NOT change the color palette.
Do NOT change the overall visual identity.

Keep:

* Bright Modern Design
* Soft Gradients
* Coursera-inspired learning experience
* Duolingo motivation
* Notion clarity
* Linear quality
* Apple-level spacing

But completely remove the feeling that the dashboard is built from stacked rectangles and separate cards.

━━━━━━━━━━━━━━━━━━━━━━

DESIGN PHILOSOPHY

Current UI feels like:

Card
Card
Card
Card
Card

This creates visual fragmentation.

The new dashboard must feel like:

One large intelligent workspace.

A continuous canvas where information naturally flows.

Content clusters should emerge through:

* spacing
* typography
* alignment
* hierarchy
* subtle backgrounds

instead of visible containers.

━━━━━━━━━━━━━━━━━━━━━━

LAYOUT PRINCIPLES

Replace:

Box-based layout

with:

Canvas-based layout

The dashboard should feel like:

* Linear
* Notion Home
* Arc Browser
* Stripe Dashboard
* Vercel Dashboard
* Apple Fitness

Content should float naturally on the page.

Avoid obvious section boundaries.

━━━━━━━━━━━━━━━━━━━━━━

HERO SECTION

Current problem:

Large empty area between content and progress ring.

New approach:

Create a fluid asymmetrical composition.

Layout:

Left:

* Welcome message
* Main headline
* Description
* Primary CTA

Right:

* Progress ring

BUT:

The progress ring should partially overlap the hero area.

Statistics should visually connect to the ring.

Create visual relationships between elements.

No isolated blocks.

━━━━━━━━━━━━━━━━━━━━━━

STATISTICS

Current:

4 separate cards.

Replace with:

Floating metrics.

Example:

Study Streak        7 Days
Average Score       91%
Focus Time          14h
Active Courses      3

Displayed directly on the canvas.

No individual cards.

No visible boxes.

Use:

* typography
* spacing
* subtle separators
* motion

to create hierarchy.

━━━━━━━━━━━━━━━━━━━━━━

RECENT ACTIVITY

Do not place inside a container.

Transform into a floating activity stream.

Visual style:

* lightweight timeline
* subtle connectors
* minimal indicators

Should feel alive and continuously updating.

━━━━━━━━━━━━━━━━━━━━━━

BACKGROUND SYSTEM

Create depth without cards.

Use:

* layered gradients
* soft glow effects
* radial highlights
* subtle mesh backgrounds

The dashboard should feel atmospheric.

Never flat.

━━━━━━━━━━━━━━━━━━━━━━

VISUAL HIERARCHY

Use:

* font size
* font weight
* contrast
* spacing

instead of:

* borders
* heavy shadows
* large containers

The page should breathe naturally.

━━━━━━━━━━━━━━━━━━━━━━

WHITESPACE

Current:

Too much unused horizontal space.

New requirements:

* Max width 1700px–1800px
* Better content distribution
* Adaptive spacing
* Fill visual dead zones

Every area of the screen should feel intentional.

━━━━━━━━━━━━━━━━━━━━━━

ANIMATION

Use Framer Motion.

Add:

* floating elements
* soft hover movement
* progress ring animation
* staggered content reveal
* smooth metric transitions

Animation must feel premium and calm.

Avoid flashy effects.

━━━━━━━━━━━━━━━━━━━━━━

COMPONENT RULES

Reduce visible containers by at least 80%.

Use containers only when absolutely necessary.

Replace cards with:

* content groups
* floating clusters
* layered composition

━━━━━━━━━━━━━━━━━━━━━━

FINAL GOAL

The dashboard should no longer look like a student project.

It should look like a commercial SaaS platform released in 2026.

Users should perceive:

* elegance
* clarity
* fluidity
* premium quality

The interface should feel like a single living canvas rather than a collection of separate boxes.

Output:

* React
* TypeScript
* TailwindCSS
* Framer Motion

Provide production-ready code and component architecture.
